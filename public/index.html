どこに登録するか

公開鍵（.pub）
接続先サーバーの ~/.ssh/authorized_keys に1行追記します。 GitHub / GitLab / Bitbucket なら「SSH keys」設定画面へ貼り付け。
秘密鍵
自分の PC だけに置きます。通常は ~/.ssh/id_ed25519（または選んだアルゴリズム名）として保存し、権限を chmod 600 に。 サーバーや Git ホストには絶対に上げないでください。
パスフレーズ付きで暗号化されます。自分の PC の ~/.ssh/id_ed25519 にだけ置き、権限は chmod 600。 使うときにパスフレーズを聞かれます（サーバーのログインパスワードとは別です）。 サーバーや Git ホストには絶対に上げないでください。
パスフレーズ
秘密鍵の解除用です。接続のたびに聞かれます。毎回の入力を避けたいときは ssh-add ~/.ssh/id_ed25519 でエージェントに登録します（エージェント起動中だけ再入力不要）。
このページについて
鍵はすべてブラウザ内（Web Crypto）で生成され、どこにも保存されません。 タブを閉じると消えます。使い終わったらダウンロード済みファイルだけ残してください。

公開鍵をリモートへ一発登録

相手サーバーへは最初だけパスワードで SSH ログインできれば十分です。 登録元の PC から次のいずれかを実行すると、対話でパスワードを聞かれたあと authorized_keys へ公開鍵が追記されます（サーバー側で手編集不要）。

上の「ユーザー名」「ホスト名」「パスフレーズ」欄を入れると、下の説明とコマンド例が差し替わります。

  1. 1. いちばん簡単 — ssh-copy-id

    デフォルト鍵（例: ~/.ssh/id_ed25519.pub）を送る場合:

    ssh-copy-id user@host

    このページでダウンロードした公開鍵を指定する場合:

    ssh-copy-id -i ~/Downloads/id_ed25519.pub user@host

  2. 2. ssh-copy-id が無いとき — cat | ssh

    cat ~/Downloads/id_ed25519.pub | ssh user@host 'mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys'

  3. 3. クリップボードの公開鍵をそのまま送る

    ページで「コピー」したあと（Linux / Wayland 例）:

    wl-paste | ssh user@host 'mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys'

    X11 なら xclip -selection clipboard -o、macOS なら pbpaste に置き換え。

  4. 4. 秘密鍵もまとめて手元へ置く → 登録

    mkdir -p ~/.ssh && chmod 700 ~/.ssh
mv ~/Downloads/id_ed25519 ~/.ssh/ && mv ~/Downloads/id_ed25519.pub ~/.ssh/
chmod 600 ~/.ssh/id_ed25519 && chmod 644 ~/.ssh/id_ed25519.pub
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@host

  5. 5. パスフレーズ付き鍵をエージェントに載せる（任意）

    接続のたびのパスフレーズ入力を減らしたいとき:

    eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

    ここでパスフレーズを一度入力すると、エージェント稼働中は省略できます。

  6. 56. ポート番号が 22 以外のとき

    ssh-copy-id -i ~/Downloads/id_ed25519.pub -p 2222 user@host
    cat ~/Downloads/id_ed25519.pub | ssh -p 2222 user@host 'mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys'

  7. 67. 登録できたか確認

    ssh -i ~/.ssh/id_ed25519 user@host

    ログイン用パスワードを聞かれずに入れれば成功です。

    秘密鍵のパスフレーズを聞かれたあと（または ssh-add 済みならそのまま）入れれば成功です。サーバーのログインパスワードを聞かれる場合は公開鍵側の登録を見直してください。

ssh 短い名前だけで繋ぐ（接続元の設定）

接続元 PC の ~/.ssh/config にホスト別名を書いておくと、 長いオプションの代わりに短い名前だけで入れます。 秘密鍵・ユーザー名・ポート・実ホスト名をここに集約します。

  1. 1. ディレクトリと権限

    mkdir -p ~/.ssh
chmod 700 ~/.ssh

  2. 2. 秘密鍵を置く（まだなら）

    mv ~/Downloads/id_ed25519 ~/.ssh/
chmod 600 ~/.ssh/id_ed25519

    パスフレーズ付きの秘密鍵です。置き場所と権限は同じです。

  3. 3. エージェントに載せる（任意）

    eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

  4. 34. 設定ファイル ~/.ssh/config を作る / 追記する

    新規作成の例（エディタでも可）:

    cat >> ~/.ssh/config <<'EOF'
Host myserver
  HostName example.invalid
  User yourname
  Port 22
  IdentityFile ~/.ssh/id_ed25519
  IdentitiesOnly yes
EOF
chmod 600 ~/.ssh/config

    各行の意味:

    • Host … 打ち込む短い名前
    • HostName … 実際の IP または FQDN
    • User … ログインユーザー
    • Port … ポート（22 なら省略可）
    • IdentityFile … このページで作った秘密鍵のパス
    • IdentitiesOnly yes … 指定鍵だけ使う
    • AddKeysToAgent yes … 初回パスフレーズ入力後、エージェントに載せられる（任意）

  5. 45. 接続

    ssh myserver

    公開鍵を相手側へ登録済みなら、これだけで入れます。

    公開鍵を相手側へ登録済みなら接続できます。初回（またはエージェント未登録時）は秘密鍵のパスフレーズを聞かれます。

  6. 56. どの設定が効くか確認

    ssh -G myserver | rg -i '^(hostname|user|port|identityfile) '

    rg が無ければ grep -E に置き換えてください。
